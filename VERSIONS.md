| v0.2.2 | **Two delivered defects fixed, plus the rehydrate gap.** (1) **Ollama backend was calling the wrong endpoint.** The maintainer's working production client (`ollama-service.js`) calls native `/api/generate` with `prompt`/`system`/`stream:false` and authenticates with an `Authorization: Bearer` header; v0.2.0 instead guessed OpenAI-compat `/v1/chat/completions` and put the token in the query string, producing `405 method not allowed` against the real gateway. Default path is now `/api/generate`, body shape follows the path, and a `?token=` in `AI_PROVIDER_URL` is promoted to the Bearer header (still redacted in logs). `/api/chat` and `/v1/chat/completions` remain supported via explicit full-path URLs; all three response shapes (`response`, `message.content`, `choices[].message.content`) are parsed. 404/405 now names the path issue and the fix. `scripts/mock_ollama.py` rewritten to mirror the real gateway — serves `/api/generate`, **405s on `/v1/chat/completions`** — so the regression that shipped cannot ship again. (2) **Log pane polled itself to death.** 400ms fixed-interval polling produced ~105 `GET /api/logs` requests during a 43s run, and at DEBUG each one logged an access line into the very pane it fed. `/api/logs` is now **long-polled**: the ring buffer signals a condition variable on each new record and the endpoint blocks up to 25s (`since=0` still returns the backlog immediately). Measured: 4 requests per 8s instead of ~20, and `/api/logs` access lines are excluded from the log at every level rather than demoted. (3) **Defect A fixed:** `rehydrate` swept only exact tokens, so a lowercased or delimiter-stripped token was neither restored nor flagged and the run reported success with a dead placeholder in the output. A looser `_MANGLED_TOKEN_RE` sweep now detects token-shaped remnants and reports them unmatched — verified: `['<<phone_01>>', 'EMAIL_01']` flagged, `ok:false`. (4) **setup.sh** names the venv path it checked and detects stale `$VIRTUAL_ENV` activation (the `(.venv)`-prompt-with-no-interpreter state that cost a debugging session). Full corpus regression: 148/148 tokens, log sanitization PASS. |
| v0.2.1 | **setup.sh: macOS python.org preflight blocker fixed.** v0.1.9's preflight hard-failed when the BASE interpreter's default TLS trust store was empty — the permanent, unfixable-by-the-user state of python.org builds on macOS (certifi lives in venvs; the base default store never fills). The gate was wrong since v0.1.6: nothing in the pipeline uses that store — pip ships a vendored CA bundle, `spacy download` uses requests+certifi, and the app's API call uses certifi explicitly. Empty store is now informational, and the TLS check that matters moved to post-install verification: the venv must load roots via `ssl.create_default_context(cafile=certifi.where())` — the exact context `model_client` builds. Reproduced the blocker (`SSL_CERT_FILE=/dev/null`, 0 default roots) and cleanroom-tested the full `--large --yes` install under that condition: preflight passes, install completes, verify reports certifi root count. |
| v0.2.0 | **Two feature mods: configurable model backend (Ollama), runtime log pane.** **Backend:** generic `AI_PROVIDER`/`AI_PROVIDER_URL`/`AI_PROVIDER_APIKEY`/`AI_PROVIDER_MODEL` scheme replaces the hardcoded Anthropic URL (`config.py:59`); legacy names (`ANTHROPIC_*`, `HOSTED_OLLAMA_URL`, `HOSTED_OLLAMA_AUTH_TOKEN`, `OLLAMA_*`) honored as fallbacks. Ollama spoken via OpenAI-compatible `/v1/chat/completions`; bare-host URLs get the path appended, `?token=` query preserved and its value auto-registered as a log secret; Bearer auth; no TLS context on http; timeout default 600s for ollama. Every failure mode names cause and fix (connection refused, 404 model tag + `ollama pull`, 401 auth, parser shape mismatch names the endpoint). **First-ever execution of `send()`, the full `/api/run` model path, and rehydration against a model response** — against `scripts/mock_ollama.py` (a test double; NOT a real model). Echo round trip byte-identical, 148/148 tokens across all 6 docs. **Log pane:** ring-buffer `logging.Handler` (deque 2000, locked) installed inside `setup_logging()` with `RedactingFilter` attached; `GET /api/logs?since=<seq>`; UI pane in About tab, 400ms polling during runs, autoscroll, level colors, `--- stage: X ---` markers. Handoff §3.2 filename hazard resolved via option (a): corpus filename stems registered as log secrets at listing time — logs show `Loading [REDACTED].pdf` from the first line. Dead uvicorn filter code removed; third-party loggers pinned (presidio to ERROR — it emits ~22 config-chatter WARNINGs per init and more per analysis). `/api/logs` access lines demoted to DEBUG so polling doesn't flood the pane it feeds. **Tests:** `scripts/check_log_sanitization.py` — all 6 docs, full NER (`en_core_web_lg`), DEBUG: zero labelled PII values in served logs. Mid-run poll verified (stage markers visible while a 4s model call blocked). `scripts/measure_token_preservation.py` — the spec §9.8 measurement harness; per-entity exact-preservation rates + failure-mode classification; run it against real models. **Known defect (found, not fixed, not authorized):** a token the model lowercases or delimiter-strips no longer matches rehydrate's strict pattern, so it is not flagged unmatched — `/api/run` reports ok while the mangled token persists in output. The measurement script catches it via sent-vs-returned counts; the app does not. All v0.1.9 open defects (thresholds, delimiters, escaping, §5.1 suppression, §7 invention check, NER false positives, thomasdavis referees, LICENSE stub) remain open. |
| v0.1.9 | **setup.sh added; four gated modes; cleanroom-tested.** `setup.sh` runs a preflight (python version, venv module, pip, TLS trust-store root count, disk space, project files) and changes nothing if it fails; then prompts for regex-only / NER+small / NER+large, or takes `--no-ner` / `--small` / `--large` / `--check` / `--yes`. Every install uses one resolved interpreter (`.venv/bin/python3`), never a bare `python3`. Writes the matching `BLACKJET_USE_NER` / `BLACKJET_SPACY_MODEL` keys to `.env`. **detect.py: Presidio's silent ~400MB `spacy.cli.download()` blocked** — the model is checked with `spacy.util.is_package()` and the tier degrades to regex-only with a message naming the interpreter, instead of downloading. **run.sh:** no longer nags about a missing model when `BLACKJET_USE_NER=0`; when the model is installed into a different interpreter it now says which one instead of telling you to re-download. **README:** quick start corrected — the old `python3 -m venv .venv` followed by a bare `python3 -m spacy download` installed the model outside the venv, which is what produced "No spaCy model installed" with the model on disk. |
| v0.1.7 | **First build with the Presidio NER tier actually executed.** Two defects found and fixed, both only observable once NER ran. (1) `pipeline.anonymize` substituted at detector offsets only, violating spec v0.4 §5.3 "same real value -> same token throughout the document"; identical values elsewhere in the document went out in the clear. Now a single document-level pass, longest-value-first, word-boundary guarded. (2) `pipeline.scan_for_leaks` matched vault values inside the app's own tokens (`CA` in `<<LOCATION_02>>`, `MA` in `<<EMAIL_01>>`), blocking correctly anonymized payloads. Tokens are now blanked before the scan. No change to `model_client`. |
| v0.1.6 | TLS: explicit certifi CA bundle for the API call, `certifi` added to requirements, and CERTIFICATE_VERIFY_FAILED now returns an actionable message instead of a raw socket error. Verification is never disabled. |
| v0.1.5 | `run.sh` exec bit restored and preserved in the archive (it had been silently reset to 644, so the documented `./run.sh` would have failed). `chmod +x` noted in README for zip users. |
| v0.1.4 | **run.sh no longer downloads anything.** spaCy model is user-installed; script reports its absence and starts regex-only. spaCy model now configurable (`BLACKJET_SPACY_MODEL`), sm/lg tradeoff documented. NER cost (download size, RAM, load time, per-doc latency) stated in README instead of omitted. NER-off warnings state the detection consequence. |
